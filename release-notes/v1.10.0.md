## Summary
Price sensors can now record long-term statistics, so Home Assistant keeps hourly minimum, maximum and average prices well past the point where ordinary state history is purged. The option is off by default and nothing changes until you turn it on.

## Breaking changes
_None._ Existing entries keep their current behaviour, and entity IDs, unique IDs and attributes are untouched.

## Added
- **Long-term statistics (#94).** A new **Long-term statistics** switch in the integration's options records hourly min / max / average prices for each fuel-type sensor. Turn it on under **Settings → Devices & Services → Tankstellen Austria → Configure**. Off by default; existing entries are unaffected until you enable it. Thanks @FHGitFH for raising it.

## Changed
- With long-term statistics enabled, price sensors publish `state_class: measurement` and drop `device_class: monetary`. Home Assistant only pairs the monetary device class with `state_class: total`, which is meaningless for a per-litre price, so the two cannot both be set. Sensors left at the default keep the monetary device class exactly as before.

## Notes
- Statistics start accumulating the moment you enable the option. Price history already in the recorder is not backfilled.
- The card is unaffected either way — its sparkline, MIN/MAX labels and refuel window read state history, not statistics. To widen what the card can see, raise `recorder.purge_keep_days`, as the card editor suggests.
- In dynamic mode the tracked radius moves with you, so a long statistics series mixes locations. The numbers are only directly comparable for a fixed location.
- Turning the option back off leaves collected statistics in place and Home Assistant raises a repair notice linking to **Developer Tools → Statistics**, where you can delete them.

## Compatibility
- Home Assistant: ≥ 2025.1 (entity-first card picker: ≥ 2026.6)
- HACS: ≥ 2.0.0
